# GEO CONVERTER — CSV → KML / KMZ

Простий український вебзастосунок для перетворення **нейтральних географічних точок** із CSV на KML або KMZ.

## Можливості

- Локальне читання CSV у браузері (дані **не надсилаються на сервер**).
- UTF-8 / UTF-8 BOM, роздільники `;`, `,` і табуляція, лапки та перенесення рядків у полях.
- Зіставлення колонок широти, довготи та назви.
- Перевірка широти (-90…90) і довготи (-180…180), пропуск помилкових рядків зі звітом.
- Збереження **всіх вхідних колонок** у KML `ExtendedData`.
- Експорт KML і стандартного KMZ (ZIP-контейнер із `doc.kml`).
- Демонстраційний CSV для тесту.
- Не потребує npm, сервера чи зовнішніх бібліотек.

## Початок роботи

Відкрийте `index.html` у браузері або розмістіть репозиторій на GitHub Pages. Завантажте CSV з колонками координат у десяткових градусах WGS84. Оберіть потрібні колонки, перевірте результат і завантажте KML або KMZ.

Приклад:
```csv
Назва;Широта;Довгота;Категорія
Музей;48.2924;25.9343;Культура
Парк;48.2870;25.9518;Відпочинок
```

## Обмеження

- Геометрія: **точки** з парою координат у WGS84. Маршрути, треки, спеціалізовані символи та інші системи координат не реалізовані.
- Координати приймаються з десятковою **крапкою**; формат DMS не підтримується.
- Макс. розмір CSV — 20 МБ; великі файли залежать від оперативної пам’яті браузера.
- KMZ записується без стискання (ZIP STORE), що є коректним форматом ZIP/KMZ.
- Сумісність із конкретними сторонніми застосунками не гарантовано.
- Не використовуйте для секретних або оперативних військових даних.

## GitHub Pages

У репозиторії є `.github/workflows/pages.yml`. У **Settings → Pages → Build and deployment** потрібно вибрати **GitHub Actions**. Після злиття в `main` workflow публікує статичний сайт.

## Структура

- `index.html` — адаптивний український інтерфейс.
- `app.js` — парсер CSV, валідація, генерація KML та ZIP/KMZ.
- `.github/workflows/pages.yml` — публікація на Pages.
